# jobs · 每日招聘雷达

[打开网页](https://lifeixiao.github.io/jobs/) · [云端更新记录](https://github.com/lifeiXiao/jobs/actions/workflows/update.yml)

面向各行业企业的招聘雷达：以企业社招、企业校招、实习为主要内容，同时保留高校、事业单位等招聘。按专业 / 岗位方向和工作城市单选 / 多选，站内预览公司、公开薪资、工作经验、职位要求、截止时间和来源，再前往招聘入口。

已配置智联公开岗位（全国多个城市）、智通直聘（制造业与中小企业）、腾讯官网、职先机等个人开发者公开聚合页、面灵公开校招 / 实习列表，以及高校人才网等补充来源。BOSS 等来源单独检查可访问性，未取得岗位时明确显示不可用；不把入口链接冒充已接入数据。个人聚合来源保留来源说明和可公开取得的官方投递链接，不把需要登录的完整描述伪装成已有详情。

## 运行方式

- **GitHub Actions 云端采集**：每日北京时间 08:23 更新，14:23 再次同步未完成或新出现的信息。GitHub 可能排队，不能保证准点。
- **GitHub Pages 静态托管**：无需 GPT、API Key、本机服务、服务器或浏览器后台常驻。不使用本机资源抓取招聘网站；采集程序主动拒绝在非 GitHub 托管运行器环境运行。
- 数据和每个来源的健康状态保存在 `data/jobs.json`，每天自动提交并发布。任务全失败也保留历史数据和故障状态，任务显示失败供排查。
- 默认保留近 120 天记录。按平台原始岗位 ID 和去除跟踪参数的链接去重，再合并跨来源中公司、岗位、城市和招聘类型一致的记录；保留全部来源链接。不同城市、职级及同一平台的不同岗位 ID 不贸然合并；一个公告的不同岗位也分别保留。截止时间冲突时明确提示核实。
- 网站超过 36 小时未成功同步会提醒；部分来源失败会显示降级提示。每日数据提交也避免仓库长期无活动，但 GitHub 账号、Actions、Pages 服务须保持启用。

## 筛选与详情

专业组、城市组内是 **或**；专业与城市之间是 **且**。支持关键词、来源类型、发布日期、截止时间排序、近 7 天发布、仅明确截止日期、隐藏过期信息。筛选条件可通过地址分享。

“专业 / 岗位方向”由公开要求和岗位名称关键词归类，包含产品、运营、销售、技工、物流、行政等企业方向；“城市”由公开结构化字段、明确工作地点或公告标题提取。不确认时单独标注。它们是检索线索，不能代替岗位资格审查。明确的 HTML 岗位表会拆成具体岗位，其余作为“公告”展示并提示可能包含多个岗位。复杂合并单元格、仅在 PDF / Excel / 图片中的条件不自动推断。

截止日期只接受与报名、申请或投递明确相关的日期，不把公告发布日和考试日当成截止日。没有具体时刻的，不虚构为 23:59；当天仍展示，精确时刻以原公告为准。“长期有效 / 招满即止”与“原文未注明”分别展示。公告统一日期不保证适用于公告中的每个岗位，请核对岗位表。

站内预览保留短摘要、结构化线索和原始链接，不托管整篇原文，不收集简历或私人账号信息。

## 数据来源与维护

来源入口、详情链接匹配规则与正文选择器在 `config/sources.json`；专业词表与城市列表在 `config/taxonomy.json`。网站内可查看每个来源的当前同步状态。受来源网站访问限制，不承诺覆盖所有招聘或所有城市。

每个来源先读取 robots.txt，禁止路径和验证页面不采集，不破解验证码，不绕过登录。按域名限速，限制列表页数和详情数量；列表摘要与完整详情区分处理。数据属于来源公开页面的每日有限快照，不代表已穷尽全网所有企业及其全部职位。页面改版后需调整适配器；新增来源只需配置对应适配器，云端日程统一负责更新。

## 开发与验证

```sh
pip install -r requirements.txt
python -m unittest discover -s tests -v
node --test tests/logic.test.mjs
python scripts/build.py
```

以上均可离线验证，**不会抓取招聘网站**。实际采集请在 Actions 中选择 **Update jobs and publish → Run workflow**。首次部署需在仓库 Settings → Pages 选择 GitHub Actions；本仓库已配置。

失败任务可在 GitHub Actions 中查看各来源摘要和日志。若 GitHub 自动停用计划任务，需重新启用 workflow；源站访问规则变化需要维护，不能承诺永远零维护。
